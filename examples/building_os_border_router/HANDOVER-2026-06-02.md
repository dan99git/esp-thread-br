## Work completed in source

### BR firmware shell and diagnostics

Current source under `firmware/esp-thread-br-bos` is a forked BR firmware project that:

- Uses Espressif ESP Thread BR vendor code from `vendor/esp-thread-br`.
- Uses local BOS components under `firmware/esp-thread-br-bos/components`.
- Starts upstream OpenThread BR.
- Starts upstream port-80 BR HTTP server.
- Registers BOS diagnostics routes on that port-80 server through the BOS fork
  web handler API.
- Does not start a second BOS diagnostics HTTP port in current source.
- Adds partitions for web storage, RCP firmware, and ledger A/B storage.
- Bundles H2 RCP firmware into the S3 image.

Important files:

- `firmware/esp-thread-br-bos/CMakeLists.txt`
- `firmware/esp-thread-br-bos/main/app_main.c`
- `firmware/esp-thread-br-bos/main/Kconfig.projbuild`
- `firmware/esp-thread-br-bos/main/esp_ot_config.h`
- `firmware/esp-thread-br-bos/partitions.csv`
- `firmware/esp-thread-br-bos/sdkconfig.defaults`
- `firmware/esp-thread-br-bos/components/bos_diagnostics_server/`

BOS diagnostics routes currently implemented in source under port 80:

- `GET /bos/status`
- `GET /bos/ledger/active`
- `GET /bos/convergence`
- `GET /bos/peers`

Diagnostics implementation deliberately returns:

- `thread.role: "not_polled"`
- `rcp.version: "not_polled"`

Reason: an earlier attempt to poll OpenThread/RCP state inside the HTTP handler caused HTTP reset/timeouts and watchdog activity around the OpenThread task. Keep OpenThread polling out of the request path until it is done safely.

- `host/runtime/server/src/routes/devices.ts`

Firmware registration source:

- `firmware/esp-thread-br-bos/components/bos_server_registration/bos_server_registration.c`
  - No longer a stub.
  - Registers IP event handlers.
  - Starts a FreeRTOS registration task.
  - Derives `device_id` from `ESP_MAC_ETH` if possible.
  - Reads server URL from NVS key `bos_reg/server_url`, or falls back to Kconfig.
  - POSTs to `/api/devices/register`.

  onto port 80.

- Firmware heartbeat does not recover from stale token/server reset.
- Current BOS diagnostics do not safely poll live OpenThread role/version.
- Ledger ingress is still mostly a stub. `GET /bos/ledger/active` reads NVS metadata, but real push/staging/digest/atomic swap is not implemented.
- ThreadTorrent-lite is handshake/ping only, not real torrenting yet.
